# 第四章总结：从内存分配到独立地址空间中的用户执行

整理日期：2026-10-25。对应本项目 [BATCH10](../../experiments/rcore-learning/BATCH10.md) 至
[BATCH22](../../experiments/rcore-learning/BATCH22.md)，以作者已经验收的实现为准。
本章总结记录现有成果，不新增任务；原批次中的实现过程、原答与审查继续保留。

本轮第四章已完成必要闭环：内存分配、独立地址空间、ELF 装载、分页用户 Trap、
普通系统调用返回，以及两个分页任务的协作调度与时钟抢占。
分页任务由公共内核事件循环组织，原第三章的 Bare 双应用调度器仍作为后续演示保留，
没有把旧调度器整体改成分页，也没有永久开启内核分页。
本轮到此收尾，rCore 暂时封存、按需查阅；接下来回 TinyOS，不进入第五章或追加扩展作业。

## 1. 本章输入与目标

第三章已经有两个应用、各自的栈、TrapContext、TaskContext，以及 yield、timer 和 exit。
这些机制解决了“谁在什么时候运行”，但当时应用按不同物理位置链接、装载，CPU 不进行分页翻译。
应用访问地址时，没有一张属于自己的页表决定它能够看到哪些物理页。

第四章逐层补齐以下能力：

```text
运行时分配元数据      → 内核堆、Box、Vec
以页为单位管理 RAM   → FrameTracker
表达地址与映射关系    → VA/PA、PageTable
管理整套区域与所有权  → MemorySet
从可执行文件准备内存  → ELF → UserImage
在不同地址空间间运行  → satp、共享跳板、分页 TrapContext
处理请求并继续用户执行 → 用户缓冲区检查、sepc/a0 返回
选择独立用户执行现场  → 分页 yield 调度、U 态时钟抢占
```

这些层次有不同职责。拿到一个 PPN，不等于已经建立映射；建立映射，不等于已经启用页表；
启用用户页表，也不等于 CPU 已经进入 U-mode。

## 2. 模块关系与启动顺序

实现集中在 [os/src/mm](../../experiments/rcore-learning/os/src/mm/mod.rs)。

| 模块 | 管理什么 | 主要产物 |
| --- | --- | --- |
| heap_allocator | 静态堆区域中的可变大小内存块 | Box/Vec 所需的全局分配器 |
| address | 地址宽度、canonical 格式、页号与索引 | PhysAddr、VirtAddr、PPN、VPN |
| frame_allocator | 指定物理页池 | 独占一个 4 KiB 页的 FrameTracker |
| page_table | 表页及 VPN→PPN 关系 | 一棵以 root_ppn 为入口的页表树 |
| memory_set | 区域、页表和 Framed 数据页 | 一套地址空间 |
| paging | 临时启用内核 Sv39 的守卫 | 验证后的硬件分页作用域 |
| elf / user_image | ELF 检查、段布局、初值与栈 | 用户 MemorySet、入口、栈界限 |
| trampoline | 共享高代码页与 S-mode 切表探针 | 两张根表之间的连续取指路径 |
| paged_user | 分页用户现场与启动返回桥 | ELF 的 U→S 执行闭环 |
| paged_syscall | 用户缓冲区检查、write/exit 分发与返回现场修正 | 处理后可继续执行的分页系统调用 |
| paged_task | 两份用户空间、现场所有者与 Ready 轮询 | 公共内核循环中的分页协作调度 |
| paged_preempt | 区分 ecall/timer，复用任务选择与系统调用处理 | 用户整数计算期间的分页时钟抢占 |

`mm::init` 依次初始化堆、页帧分配器，并运行各阶段演示。
每个后期演示在完成检查后恢复 Bare、释放自己的临时资源，才进入下一阶段。
因此日志里先后出现的页数，不能相加成一个永久驻留的总量。

## 3. 内核堆：动态使用固定区域

[BATCH10](../../experiments/rcore-learning/BATCH10.md) 的堆来自普通 BSS 中的
`HEAP_SPACE`，大小固定为 256 KiB，按 4 KiB 对齐，由链接结果决定位置。
动态变化的是其中哪些内存块已分配、哪些空闲，以及对象何时产生和销毁。

本项目的堆没有自动增长，也没有从物理页分配器申请新页。
“动态分配”并不要求整块堆的总容量必须伸缩。

```text
Box / Vec 等拥有者  → 请求若干字节及对齐 → 堆分配器 → HEAP_SPACE 内的块
页表 / 用户数据页   → 请求一个完整页     → 页帧分配器 → 独立页池中的 4 KiB
```

局部 `Box` 可以理解为持有堆上对象的拥有者；`Vec` 管理元素指针、len 和 capacity。
这些拥有者本身可以放在栈上、寄存器中或其他对象里，并非类型规定只能在栈上。
本例 `Vec<usize>::new()` 尚未申请元素缓冲区，push 才可能触发分配。
len 是已初始化元素数，capacity 是当前无需重新分配就能容纳的元素数。

`drop(values)` 消费 Vec，销毁元素并归还缓冲区；之后不能继续使用这个变量。
它不把整块静态堆交还给页帧分配器，也不承诺把释放的字节清零。

堆只能初始化一次。把存活堆再次登记为空闲，会破坏现有分配关系。
持有分配器锁时再创建 Box/Vec，会在内部再次请求同一把锁，造成自我等待。
所以读取统计后先释放锁，再进行分配、销毁或其他可能间接分配的操作。

## 4. 地址类型：先区分表示，再谈翻译

[BATCH11](../../experiments/rcore-learning/BATCH11.md) 为 VA、PA、VPN、PPN 建立独立类型。
即使两个值数值相同，其语义也不同；不同类型帮助编译器拦截混用。

| 操作 | 得到什么 | 是否查询页表 |
| --- | --- | --- |
| VirtAddr::floor | 所属虚拟页号 VPN | 否 |
| VirtPageNum::to_addr | 虚拟页首地址，偏移为零 | 否 |
| PhysAddr::floor | 所属物理页号 PPN | 否 |
| PhysPageNum::to_addr | 物理页首地址，偏移为零 | 否 |

`floor` 和 `to_addr` 都没有找到另一类地址。
真正翻译还需要由 VPN 查到 PPN，再接回原来的页内偏移。

Sv39 的地址信息分为：

```text
VA bits[38:30]  bits[29:21]  bits[20:12]  bits[11:0]
      VPN[2]        VPN[1]        VPN[0]       offset
        9             9             9           12 位
```

4 KiB = 2^12，因此偏移用 12 位表示；剩余 27 位分成三级，每级索引 512 项。
`indexes()` 返回从根到叶的 `[VPN[2], VPN[1], VPN[0]]`。
例如 `0x80401234` 的结果为 VPN `0x80401`、索引 `[2, 2, 1]`、偏移 `0x234`。
数组下标 0 对应 VPN[2]，不能把数组位置与架构层级编号混为一谈。

完整地址仍使用 64 位表示，其 bits[63:39] 必须全部等于 bit38：

- bit38 为 0，高 25 位全为 0；bit38 为 1，高 25 位全为 1。
- `0xffffffc000001234` 满足这一规则。
- `0x0000004000000000` 的 bit38 为 1、高位却为 0，因此不是合法 canonical 地址。

提取高半区 VPN 时，先保留低 39 位再右移 12 位，避免把符号扩展带进 27 位页号。
反向得到 VA 时，需要按 bit38 恢复高位扩展。
格式合法只代表地址表示正确，不保证已经映射或具有访问权限。

## 5. 页帧分配：页号与拥有者是两件事

[BATCH12](../../experiments/rcore-learning/BATCH12.md) 的当前页池为
`[0x80440000, 0x81000000)`，共 3008 个 4 KiB 页。
这是当前布局下明确划出的范围，不是 QEMU 所有空闲 RAM 的自动发现结果。
页池排除了固件、内核、旧应用装载窗口和高端 DTB 所在区域。

起点必须在保留区域结束之后向上对齐，终点必须保证页完整落在合法范围。
不能仅从 `ekernel` 开始就把其后所有 RAM 都视为空闲，因为其中还可能有其他保留内容。

分配器有两类空闲页来源：

```text
recycled：此前交出、现在已经归还的页号
[current, end)：从未顺序交出的页号
```

分配先弹 recycled；没有回收页时，才交出 current 并加一。
归还页只登记到 recycled，不让 current 倒退。
例如 A、B、C 已分配而只归还 B，倒退 current 就可能再次交出仍在使用的 C。

```text
free   = end - current + recycled.len()
in_use = current - start - recycled.len()
```

全部归还后 current 不必回到 start；只要空闲集合完整，free 仍恢复 3008。
`recycled.len()` 是可复用页号数量，capacity 是元数据记录容量，都不是存活页数。
Vec 存的是 `usize` 页号记录，页的 4096 字节内容在另一处 RAM。

`PhysPageNum` 可以复制，因为它只是数字；`FrameTracker` 不可复制，因为它独占页的生命周期。
移动 Tracker 是转移所有权，不会立即归还页，也不会产生第二个拥有者。
Tracker 的 Drop 调用页分配器归还页，重复回收则说明内部所有权不变量已被破坏。

页在分配给新拥有者之前清零，归还时只记录页号。
清零发生在页分配器解锁之后：该页已从空闲集合移走，仍由新拥有者独占，
不必为了写满 4096 字节一直锁住分配元数据。
持有帧分配器锁时销毁 Tracker，会经 Drop 再次获取同锁，必须避免。

## 6. PageTable：一个对象管理一棵树

[BATCH13](../../experiments/rcore-learning/BATCH13.md) 的 `PageTable` 包含根 PPN 和
`Vec<FrameTracker>`，后者拥有这棵树中的所有表页。
**一个数据页不需要一个 PageTable 对象，也不总需要新分配一个表页。**
多个 VPN 可以共用上层路径，甚至共用同一张 L0 表中的不同叶项。

一张表页为 4096 字节，每项 PTE 为 8 字节，所以容纳 512 项。
编码关系与地址关系分别是：

```text
PTE bits = (PPN << 10) | flags
物理页首 = PPN << 12
```

左移量来自不同的布局。PTE 的低 10 位不是物理地址偏移：低 8 位是架构标志，
bits[9:8] 是软件保留位，本项目不使用。
V 仅表示表项有效，不能独自证明它是叶项。
本实现要求中间项只带 V；末级叶项至少带 R 或 X，并拒绝 W=1、R=0。
当前仅支持 4 KiB 叶，不支持上层大页叶项。

以 `0x40001234` 为例：

```text
L2[1] → L1 的 PPN
L1[0] → L0 的 PPN
L0[1] → 数据页 PPN
最终 PA = (数据页 PPN << 12) + 0x234
```

`0x40002567` 的索引为 `[1, 0, 2]`，可以共用上述三张表页。
软件 `translate_va` 只沿表计算结果，不分配、不按用户 VA 解引用，也不激活硬件分页。
查询成功不等于 CPU 正在使用该根表；硬件访问还需按实际权限和特权级检查。

PageTable 只拥有表页。PTE 里记录数据 PPN，不接收该数据页的所有权。
数据拥有者必须活得足够久，不能映射完就释放，否则旧映射可能指向下一个拥有者的数据。
补齐缺失路径时先准备所需表页，再发布父项，避免分配失败留下半条新路径。

## 7. MemorySet：整套映射与数据页归属

[BATCH14](../../experiments/rcore-learning/BATCH14.md) 至
[BATCH16](../../experiments/rcore-learning/BATCH16.md) 将单页关系提升为区域管理。

```text
MemorySet
  ├─ 一个 PageTable：包含整棵页表树及其表页拥有者
  ├─ 多个 MapArea：起止 VPN、权限、映射方式的数值描述
  └─ 多个 FramedPage：VPN 与数据页 FrameTracker 的对应关系
```

MapArea 是可复制描述，不是对页面的借用，也没有隐含的数据页所有权。
FramedPage 才持有实际分配的数据页。

Identical 表示 VA 与 PA 数值相同，本实现不为这些既有物理区域新造数据页拥有者。
Framed 表示为每个 VPN 分配并拥有物理页，不强制 VA 必须与 PA 数值不同。
U 位控制用户访问权限，并不把执行中的 CPU 切成 U-mode。

内核地址空间包含四区，全部 U=0：

| 区域 | 权限 | 内容 |
| --- | --- | --- |
| text | R/X/A | 内核机器码 |
| rodata | R/A | 只读常量 |
| `[sdata, ekernel)` | R/W/A/D | 已初始化数据、BSS、启动栈、静态堆等 |
| 物理页池 | R/W/A/D | 内核操作表页与数据页的恒等映射窗口 |

恒等映射仍经过 MMU 和 PTE 权限检查。开启分页后，内核取指、栈访问同样需要有效映射。
BSS 不是栈的同义词；只是当前链接布局把若干静态栈区域放在 BSS 存储范围中。
清 BSS 的 sbss 仍位于正在使用的启动栈之后，避免擦掉当前调用现场。

构造前检查所有区域对，不要求输入已经排序；半开区间相邻合法、相交拒绝。
构造失败时 `?` 返回错误并触发已建立局部拥有者的 Drop，未完成空间不会逃逸。
正常字段顺序与错误路径局部声明顺序都安排为先销毁表页，再销毁数据页。
但这只处理软件所有权，**不会自动保证活动页表已经退出硬件使用**。

## 8. 跨页初始化与 guard

内核准备非恒等映射用户页时，不能把用户 VA 转成指针就直接写。
B16构造时在Bare、地址空间尚未激活且没有外部读写者的条件下，按VPN找到自己的Tracker，
再通过可直接访问的物理页内存写入。后续演示也会在核验过的内核页池恒等映射下、用户暂停时访问自有页；
都要求页内借用在用户或汇编再次运行前结束。
因此可以初始化以后仅允许 R/X/U 的代码页，不需要为了复制而永久给代码加 W。

每次写入的长度为：

```text
min(4096 - 当前页内偏移, 尚未复制的字节数)
```

从偏移 4093 写 8 字节，先写本页 3 字节，再重新查找下一 VPN 的拥有者写 5 字节。
VA 连续不保证 PA 连续，不能只把第一个 PA 指针继续加到下一页。

复制前完整检查整个范围：加法不溢出、落在同一 Framed 区域内、每个目标 VPN 都有拥有者。
因此跨入未映射 guard 的请求会在第一次写入前返回 Err，不留下“前几字节已经写了”的污染。
这是软件预检带来的原子拒绝，不是写到 guard 后依靠 MMU 异常回滚。

guard 是刻意不映射的一页，在分页运行时可以使落入其中的访问触发缺页。
它不能保证捕获所有越界；直接跳过该页的错误地址仍需其他检查处理。

## 9. ELF：文件描述怎样变成用户内存

[BATCH17](../../experiments/rcore-learning/BATCH17.md) 使用独立的 `image_demo.elf`。
ELF 是可执行文件格式，不是 Linux 专属；一个 ELF 文件也不自动成为根进程。
本项目内核仍由 ELF 转成 BIN 后交给 QEMU 预加载，而这里解析的是用户应用 ELF。

装载依据 program header 中的 PT_LOAD，不依赖 section header 的节名：

| 字段 | 含义 |
| --- | --- |
| p_offset | 这一段的初值从 ELF 文件哪里开始 |
| p_vaddr | 这一段在用户虚拟地址空间的原始起点 |
| p_filesz | 从文件复制多少字节 |
| p_memsz | 在用户内存中保留多少字节，必须不小于 filesz |
| p_flags | 段需要的 R/W/X 权限 |

区域起点向下取整、内存终点向上取整，以便建立完整页映射；
复制初值时仍使用原始 p_vaddr，不能改成取整后的页首，否则内容位置会错。
只复制 p_filesz；其后到 p_memsz 的字节由新页的初始清零提供，包括 BSS。
不从文件强行读取 p_memsz，也不把整个应用内容压到内核栈上。

ELF 的 PF_X/PF_W/PF_R 数值为 1/2/4，与 PTE 对应位的位置不同，必须逐位转换。
用户段加 U、A，可写段加 D；V 由 PageTable::map 安装。
解析器还检查格式、架构、大小、溢出、文件边界、对齐和可执行入口等。
当前是受限静态 ELF 装载器，不处理动态链接、TLS、重定位，也不合并重叠段页权限。

固定示例布局如下：

```text
0x40000000                 text，R/X/U，入口
0x40001000                 rodata，R/U
0x40002000 … 0x40004000    data + BSS，R/W/U，两页
0x40004000 … 0x40005000    guard，无映射
0x40005000 … 0x40007000    用户栈，R/W/U，两页
```

3 个 LOAD 占 4 个数据页，加 2 页用户栈，共 6 页；映射低端用户区需要 3 个表页。
段文件大小分别为 116、17、8 字节，内存大小分别为 116、17、5016 字节。
这是 B17 的 image_demo 当时的 ELF 结果；B20—22 复用区域布局，但新样例的机器码与文件大小可以不同。
`UserImage` 返回 MemorySet、入口、guard 和栈界限，并不在构造函数中启用 satp。

两张不同根表可把同一个用户 VA 指向不同 PA，这是进程地址隔离的基础。
因此“应用都使用 0x40000000”本身不冲突；当前选中的根表决定实际到达哪里。

## 10. 共享跳板：先保证切表期间仍能取指

[BATCH18](../../experiments/rcore-learning/BATCH18.md) 先只做 S-mode 内核表→用户表→内核表往返。
写 satp 不改变 PC、sp 数值，也不改变 CPU 特权级。
所以在低内核代码处直接切到未映射这段代码的用户表，会失去继续执行所需的映射。

本项目在两根中建立：

```text
同一个 VA 0xfffffffffffff000 → 同一块内核镜像代码物理页
权限 R/X/A，U=0，W=0
```

跳板代码在共同高 VA 执行，切表前后同一个 PC 数值仍能找到对应指令。
只把同一个 PA 映射到两张表的不同 VA，不会使 CPU 自动修改 PC 去往另一别名。
选择同 PA 也省去复制与维护两份代码的工作；不是因为两个程序同时争用页表导致特权冲突。

跳板已经属于永久存活的内核镜像，不从页池新申请代码页，也不新增数据页 Tracker。
但两张既有根表各需要一张高端 L1 和一张 L0，共新增 4 个表页。
B18 的内核表由 9 增为 11，用户表由 3 增为 5，加 6 个用户数据页，共 22 页。

用户表没有映射低内核栈，所以 S-mode 探针切到它以后只使用寄存器，不按原 sp 访存。
必须先回到内核表再 ret，才能安全回到低代码与原调用栈。
完整 Bare、satp、特权级与同步语义见 [Bare/Sv39/Trap 专题](BARE_SV39_TRAP.md)。

## 11. 真正运行分页 ELF：用户现场与内核续点

[BATCH19](../../experiments/rcore-learning/BATCH19.md) 新增私有 `PagedTrapContext`：

| 内容 | 字节偏移 | 保存谁的信息 |
| --- | ---: | --- |
| x[0]…x[31] | 0…248 | 用户整数寄存器，x[2] 是用户 sp |
| sstatus / sepc | 256 / 264 | 返回用户所需状态、用户 PC |
| kernel_satp | 272 | 陷入后要恢复的内核根表 token |
| kernel_sp | 280 | 保存启动调用续点之后的内核 sp |
| trap_handler | 288 | 本批低地址汇编返回桥入口 |

它是 37 个 RV64 字，共 296 字节，独占一页。
旧的 272 字节 TrapContext 不变，继续服务原 Bare 双应用。
现场高 VA 为 `0xffffffffffffe000`，紧邻跳板下方，在两根中映射同一 PA，权限 R/W/A/D、U=0、X=0。
它复用已有高端 L0，只新增 1 个现场数据页，因此本批共 23 页。

启动入口另外在原内核启动栈上保存 ra、gp、tp、s0…s11：15 个字为 120 字节，
栈帧取 128 字节保持对齐，帧地址写入 kernel_sp。
这份内核续点与用户 296 字节现场是两个对象；没有额外申请内核栈页。

初始用户 x 全零，只把 x[2] 设为用户栈顶、sepc 设为 ELF 入口。
使用 `status & !mask` 清除 SPP/SIE/SPIE/SUM/MXR/FS/VS，保留其余合法配置。
本演示只运行整数代码，不启用 S 中断源，不保存浮点或向量状态。

真实往返顺序为：

```text
S + Bare：构造所有页、检查映射与入口
 → S + 内核表：保存原启动调用续点
 → S + 用户表：高跳板恢复用户现场
 → sret
 → U + 用户表：_start → 清 BSS → main → exit(0) → ecall
 → S + 用户表：高 trap 入口保存用户现场
 → S + 内核表：恢复内核 sp，跳低返回桥
 → ret 回原 Rust 调用
 → 恢复 Bare/CSR，检查保存的退出现场，回收资源
```

`ecall` 发生时硬件记录 sepc、scause、stval 和特权/中断状态并跳 stvec，
**不会自动换 satp，也不会自动换 sp**。
因此跳板必须在用户表中可取指，现场页必须在用户表中可供 S-mode 保存寄存器。
两者设 U=0，是为了阻止用户直接执行跳板或篡改内核返回字段，并不妨碍陷入后的 S-mode 使用。

`sscratch` 预存高现场 VA；入口用它与用户 sp 交换，再把原用户 sp 保存到 x[2]。
恢复用户时必须最后才加载 `sp = x[2]`，否则前面的现场 ld 会误读用户栈。
退出时先取完 kernel_satp/kernel_sp/trap_handler，才能切表、换 sp 并跳转。
桥还要恢复内核 gp/tp 和被调用者保存寄存器，保证回到 Rust 后仍符合普通 C ABI。

B19 只接受首次 trap 为 `ecall`、a7=93、a0=0，证明用户执行到正常 exit。
用户不会继续恢复，所以无需 `sepc += 4` 或写回用户 a0。
这一阶段还没有普通分页 syscall 返回或 timer 调度；B20—22 在保留该演示的基础上继续补齐。

## 12. 分页系统调用：检查用户内存，再恢复原用户

[BATCH20](../../experiments/rcore-learning/BATCH20.md) 将“收到第一次 Trap 就结束”扩展为多次往返。
用户执行 write 后，保存的现场页、用户数据和用户栈仍存活；内核处理请求，修改现场副本并写回，
再调用原 `__paged_enter` 恢复同一个用户。不会重新装载 ELF，也不会每次重置入口和寄存器。

write 的参数为 a0=fd、a1=用户 VA、a2=长度，调用号 a7=64；本实现仅支持 fd=1、最多 256 字节。
切回内核表后，用户 VA 数值不能直接当作内核指针：当前 MMU 使用内核根表，那里没有用户低地址映射。
读取路径是：

```text
用户 VA → 用户 MemorySet 的叶权限与拥有者
        → 对应 FrameTracker 的物理页和页内偏移
        → 内核页池恒等映射 → 内核局部缓冲区 → SBI 输出
```

非空请求先检查长度、地址加法溢出、canonical 格式，再完整检查每个地址的 V/U/R 和数据页拥有者。
这些条件全部成立后才填充内核缓冲区，完整复制成功后才输出，故失败返回 -1 且没有部分前缀输出。
V/U/R 说明该用户映射可读；拥有者说明数据页仍属于这个空间、生命周期有效，两者不能互相替代。
fd=1、长度为零时直接返回 0，不转换或访问缓冲区地址。

这与第 8 节的装载初始化有不同目的：初始化可以通过拥有者写入将来的 RXU 代码页，
系统调用则必须尊重用户当前的读权限，不能以“内核能读到 PA”为由绕过权限检查。
此时用户已暂停，内核页池恒等映射已经核验；所有页内 Rust 引用都在再次进入用户或汇编前结束。
跨越执行期保留的是拥有者和数值形式的现场副本，不是数据页上的引用。

普通调用处理完毕，无论返回长度还是 -1，都必须执行：

```text
现场.sepc += 4                  跳过已处理的 ecall
现场.x[10] = 返回值的寄存器位模式  恢复后由用户 a0 读回
```

用户包装按 isize 读取返回寄存器，因而 `-1 as usize` 保存的位模式仍能读回 -1。
其他用户寄存器保留；恢复时继续原调用之后的指令。exit=93 返回退出结果，不再恢复该用户，
所以不推进退出现场的 sepc。未知调用返回 -1，属于普通返回。

B20 的固定链为只读段输出 23 字节、跨 guard 拒绝、栈缓冲区输出 22 字节、exit(0)，
共 4 次 U ecall、3 次恢复。错误缓冲区前两字节 QZ 合法、后两字节落入 guard，
验收直接核对原始输出字节数为零；全程复用同一批 23 页。

## 13. 同 VA 的两个用户任务：选择页表和完整现场

[BATCH21](../../experiments/rcore-learning/BATCH21.md) 把同一个 `task_demo` ELF 装载两次。
两个任务的入口都是 `0x40000000`、数据起点都是 `0x40002000`，用户栈范围也相同，
但各自的根表将这些 VA 映射到不同的自有物理页。因此同一个数值地址可分别保存任务 id 和私有计数。
这不是同一任务把代码、数据和栈放在同一地址；相同的是两个任务中各对应区域的 VA。

| 资源 | 两个任务的关系 |
| --- | --- |
| ELF 文件字节 | 使用同一份输入，分别装载，不复制页拥有者 |
| 用户根表和内容页 | 各自独立，token 与对应数据 PA 不同 |
| 用户现场 | 各自一页，保存各自的 x[0..31]、sstatus、sepc 等 |
| 跳板 | 同高 VA 映射同一静态代码 PA，RX/U0 |
| 内核空间与执行栈 | 共用一张内核表、同一个内核循环和原启动栈 |

task0 的现场槽为 `TRAMPOLINE - PAGE_SIZE`，task1 为 `TRAMPOLINE - 2 * PAGE_SIZE`。
各用户表只映射自己的现场槽，公共内核表映射两者；两个槽的 PA 不同，均 RW/U0。
原汇编通过传入地址与 sscratch 寻找现场，因而可以复用，不必再写一份寄存器保存代码。

一个用户 Trap 已经通过返回桥回到公共 Rust 调用点时，没有分别挂起、还需恢复的阻塞内核调用链。
循环可以直接选择下一任务的用户 token、现场槽和完整寄存器状态，再经跳板执行 sret。
恢复用户 sp（x[2]）只是切换完整用户现场的一部分；还要切用户根表、恢复用户 PC、状态与其余通用寄存器。
当前这种组织不需要第三章的 `__switch` 或每任务内核栈；旧 Bare 路径仍保留原 TaskContext 机制。

状态规则为：

```text
首次选择：Ready → Running
普通 write / 未知调用返回：保持 Running，恢复当前用户
yield(124)：先准备返回值 0 和 sepc+4，再 Running → Ready，选择下一个 Ready
exit：Running → Exited，不再恢复；选择下一个 Ready，没有则结束
```

环形查找从下一个槽开始，扫描 `1..=TASK_COUNT`，当前任务是最后一个候选。
仅余一个任务时，它在 yield 后仍为 Ready，可以选中自己；Exited 永远不再入选。
理由是当前任务仍能继续运行，与可能存在的未来新任务无关。

资源由一张公共内核表和两份 PagedTask 保活：

```text
公共内核表                              11 个表页
每个用户：低区 3 表页 + 高区 2 表页       5 个表页
每个用户：LOAD 占 4 页 + 用户栈 2 页      6 个内容页
每个用户：独占分页现场                   1 个现场页
合计：11 + 2 × (5 + 6 + 1)              35 页
```

用户的 5 个表页用于描述映射，6 个内容页用于存放代码、数据和用户栈，二者不是一类资源。
两个现场槽共用已有高端 L0，映射第二个槽不另增表页；跳板使用已有代码页，
原启动栈的 128 字节调用续点也不计入本次从页池新分配的 35 页。

B21 验收为 5 次 write、5 次 yield、2 次 exit、1 次未知调用，共 13 次 U ecall。
其中 11 个普通调用有后续恢复，加上两个任务各自首次进入，共 13 次 sret。
最后观察到 task1 yield 到自己，两个任务均正常退出；35 页在循环中保持，结束后归还。

## 14. 用户运行中的时钟抢占

[BATCH22](../../experiments/rcore-learning/BATCH22.md) 让两个 `preempt_demo` 任务持续做整数计算，
用户忙循环不调用 yield 或其他系统调用，由 S timer 打断并复用 B21 的任务选择。
每次仍先保存完整用户现场、切回公共内核表与启动栈，再由内核循环处理原因。

| 原因 | 精确 scause（RV64） | 是否准备 syscall 返回 |
| --- | --- | --- |
| U ecall | 8，最高中断位为 0 | 普通返回修改 sepc/a0；exit 不恢复 |
| S timer | `(1usize << 63) \| 5` | 保留原 sepc 和全部用户通用寄存器，包括 a0 |

原始值 5 没有最高中断位，是同步异常，不是 timer。
timer 没有完成一条应该跳过的 ecall，也没有用户等待的 syscall 返回值，
所以不能复用普通返回的 `prepare_resume`；否则会跳过普通指令、覆盖计算中的 a0。
用户代码还可能含两字节压缩指令，不能假定任意被中断位置都应加 4。

timer 路径先设置下一次绝对 deadline，再把当前任务从 Running 改回 Ready、选择下一任务。
这复用了 Yield 的状态规则，用户没有执行 yield 系统调用；被暂停任务的现场仍保持原值供下次恢复。
deadline 来自 `now + TIMER_INTERVAL`；当前时基为 10 MHz、间隔 100000 ticks，即 10 ms，
它不是 CPU 主频。重新武装会处理本次已到期的事件，避免恢复用户后立即因旧 pending 反复陷入。
固定interval不保证用户CPU时间片严格相等，设置deadline后还存在内核处理与恢复等开销。

本批只打开 `sie.STIE`，公共内核处理期间保持 `sstatus.SIE=0`，没有内核中断嵌套。
用户处于 U-mode 时，S 级中断的递送不受 sstatus.SIE 的值限制；
仍需满足委派、pending 和 sie 中相应使能，所以 STIE 仍须设置。
这也解释了为什么 B19 的初始 SPIE 清零逻辑能够继续使用，而无需打开内核 SIE。

样例的 stop 字段仅用于有界观察：实际见到双向抢占后让 task0 完成，
task0 退出后还要观察 task1 的 timer 自切换，才让 task1 完成。
它不是通用系统调用或生产调度策略；两个用户任务各输出一次 done、各 exit(0)，共 4 次 U ecall。
若实际 timer 数为 T，则有 T 次 timer 后恢复、2 次 write 后普通恢复，以及 2 次首次进入。

本次作者验收观察到 T=5，双向 timer、自切换、私有计算进展与完整现场保留均通过；
5 是该轮观测，不是必须精确重复的固定次数。唯一拒绝路径为精确分类函数拒绝原始 cause=5，
不改变硬件或资源，不另行制造致命用户故障。
证据为 `.cache/batch22-author-review-l9k_umtl/`，该次 QEMU 主动退出 0，35 页、堆和八项 CSR 均恢复。
验收时存在一条未使用 Exited 导入警告，不影响功能结论；本次文档整理不重新运行测试。

## 15. 活动页表、同步与回收

页表对象的生命周期必须覆盖硬件使用期。
仅 Drop 一个活动根表，或只归还其数据页，都会留下硬件仍可使用的悬空映射。
危险不必等待主动刷新 TLB：缓存未命中时，硬件随时可能重新走 satp 指向的表。

不使用 timer 的闭环在低地址内核返回后恢复原 Bare，再执行全量 `sfence.vma`，最后销毁页表与数据页。
不能在高跳板处直接 Bare：PC 数值仍是高 VA，此后无法继续按那个数值取物理指令。
恢复 Bare 不是释放内存，页帧归还由之后的拥有者 Drop 完成。

切到 Bare 本身立即生效，不需要等 SFENCE 才停止地址翻译。
但写 satp 不自动清掉旧翻译缓存，也不能替代页表修改同步；当前每次切根都用全量 SFENCE。
`fence.i` 则用于使本 hart 的后续取指看到刚写入的 ELF 机器码，不能由 SFENCE 代替。
这里都不是“把普通数据缓存清空”。

私有活动守卫保活所有资源，演示期间没有 Rust 现场内容引用跨越汇编或用户写入。
B19—22 返回时恢复八项 CSR：satp、stvec、sscratch、sstatus、sie、sepc、scause、stval。
单用户两根先销毁、独占现场页后销毁；双用户总拥有者先销毁公共内核空间，
再销毁各任务的用户空间，随后释放其现场页，避免借用现场 PA 的表仍存活而页已被复用。
构造双任务时，先让总拥有者接管公共内核表和两个任务，再向内核表发布现场别名，
使第二次映射失败也能按同一字段顺序退出，而非误依赖局部变量逆序销毁。

B22 还要先结束本批硬件定时事件：

```text
全部用户退出，当前已回到低地址代码 / 公共内核表 / 原启动栈
 → 清 sie.STIE
 → SBI 设置 deadline=u64::MAX，取消本批定时事件
 → 恢复原八项 CSR 与 Bare，完成地址翻译同步
 → 销毁公共内核表、两个用户空间和两个现场页
 → 后续旧 Bare 演示的 timer::init 重新设置自己的 deadline
```

停止 timer 的 SBI 结果必须处理；即使停止失败，也要先恢复 CSR/Bare，再报告失败，
不能输出“已经完整恢复”的正常结论。本批开始时旧调度定时器尚未初始化，
因此只撤销自己的事件，不承诺保存并恢复一个先前运行系统的硬件 deadline。

本批集中保留两份用户空间，等全部结束后回收，与当前现场借用映射和暂无 unmap 的设计相配合。
这不表示一般内核必须等所有任务退出才释放一个任务，也不表示将状态改成 Exited 就会立即释放资源。

将来内核可以一直使用自己的有效根表；用户退出后切回它，再回收用户空间即可。
每次退出都恢复 Bare 是当前临时启动演示的安排，不是操作系统必守的通用步骤。
